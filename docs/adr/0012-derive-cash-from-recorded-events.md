# Derive bank cash from recorded events

帳務起始日後，Personal Asset OS以期初現金、已完成的股票交割及Owner確認的現金事件推導銀行現金餘額，不允許直接覆寫餘額。手動現金事件支援存入、提領、帳戶間轉帳、利息、銀行費用及其他調整；它們只記錄實際帳務，不執行網銀轉帳，也不得重複登記由股票待交割款自動產生的現金變動。

## 帳戶間轉帳

兩個系統內銀行帳戶之間的轉帳由一次操作建立等額的來源流出與目的流入，兩端共享轉帳識別並須一起成功或一起失敗，不得只確認其中一端。轉帳本金不改變資產總額；若銀行另收手續費，須以獨立銀行費用事件記錄。轉入或轉出系統外帳戶時只記錄系統內一端，並保留外部對象說明。

## 流出資金限制

確認提領、轉出、銀行費用或其他現金流出前，須依事件發生日重新計算銀行現金及所有未付款買入待交割義務。若流出會使現金餘額為負，或使交割可用現金低於零，整筆現金事件必須拒絕且正式帳務保持不變；系統不得以尚未交割的賣出應收款補足，Owner須先補登流入或修正相關資料。系統須記錄被拒事件、銀行帳戶、發生日、流出類型與金額、判定時現金、未付款買入義務、交割可用現金及拒絕原因；系統內轉帳被拒時兩端都不得生效。

## 補登現金事件

Owner可按實際發生日補登帳務起始日後遺漏的存入、提領、轉帳、利息、銀行費用、其他調整或現金股利。確認前須從實際發生日完整重算後續銀行現金、交割可用現金與受影響交易；任何負現金、待交割買款不足或其他規則衝突都整筆拒絕並列出全部受影響紀錄。系統內轉帳補登時兩端須一起建立；成功補登須保存實際發生日、系統補登時間、Owner確認時間及重算範圍與結果。

## 稽核與更正

每筆現金事件須保存銀行帳戶、發生日、類型、流入或流出方向、正數金額、Owner確認時間、說明及選填來源參考。已確認事件不得直接修改或刪除；更正須建立關聯紀錄、保留更正前後內容與理由，並重新驗證後續交割可用現金及所有受影響交易。
